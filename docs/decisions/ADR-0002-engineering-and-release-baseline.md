# ADR-0002：P00 工程、数据库与初始发布验收基线

- 状态：Accepted
- 日期：2026-11-16
- 决策级别：S1 / A1
- 关联阶段：P00、P02、P11、P64.F、P64

## 背景

P00 必须在代码出现前冻结足以约束后续实现的工程方向、首个真实数据库、目标部署资源和性能档位，同时不能把尚未执行的性能测试写成成功。

## 决策

### .NET 与 SDK

- 目标框架保持 `.NET 10` / `net10.0`，与三份设计基线一致。
- 2026-11-16 核查时 .NET 10 仍为受支持的 LTS；即使 .NET 11 已发布，也不在 P00 静默升级目标框架。
- P02 必须在实际 CI/开发环境执行 `dotnet --info`，选择**实际安装并验证过的 10.0.xxx SDK** 写入 `global.json`。
- `global.json` 使用精确 SDK 版本，`rollForward` 采用 `latestPatch`，`allowPrerelease=false`。
- 在 P02 实测前不填造 SDK feature band 或补丁号。

官方支持政策参考：https://dotnet.microsoft.com/en-us/platform/support/policy

### 首个真实关系数据库

- 首个验收数据库选择 **PostgreSQL 18**。
- P11 开始真实集成时固定受支持的 18.x 补丁版本与容器镜像 digest，并记录实际隔离级别、事务、超时和乐观并发行为。
- 2026-11-16 可用的当前 18.x 文档版本为 18.7；这只是 P00 选择时的外部基线，不冒充 P11 已完成集成。
- Core 不依赖 PostgreSQL 类型；领域只依赖自己的 Persistence Port，SQL/驱动留在 Infrastructure/Platform Adapter。

官方文档参考：https://www.postgresql.org/docs/18/

### 初始部署与发布性能档位

P64/P66 之前的目标环境冻结为：

| 项目 | P00 决策 |
|---|---|
| OS / 架构 | Linux x64 |
| 部署形态 | 单进程模块化单体，容器化运行 |
| CPU 限制 | 4 vCPU |
| 内存限制 | 8 GiB |
| 发布目标档位 | 中档：10 World / 总计 10,000 实体 |
| 逻辑步长 | 50 ms 初始配置 |
| GC | Server GC，具体参数在 P64.F 冻结 |
| 数据库 | PostgreSQL 18，数据库资源独立于服务器 4 vCPU / 8 GiB 限制 |

这些是**设计目标和验收环境约束，不是已验证性能结果**。活跃实体比例、AI/Status 密度、命令速率、预热/重复次数及绝对 p99/分配/GC 阈值由 P64.F 在首次模块集成前冻结；不得在看完结果后为了通过而降低阈值。

### 可靠性初始目标

沿用 ROADMAP 的启动目标：

- 已确认 Committed 的经济/权益变更：RPO 0。
- 非关键检查点窗口：目标 ≤ 30s。
- 目标配置恢复：目标 ≤ 5min，P66 以真实备份体量验证。
- 最终发布配置：连续 24h 长稳；日常/夜间短跑不替代最终证据。

## 后果

后续 P02、P11、P64.F 必须把“选择”转换成可执行、可复现的工程与测试证据。任何改变目标框架、首个数据库主版本、资源限制或发布档位的行为都需要显式记录原因和影响，不能仅修改 CI 或配置文件。
