# P10 — Platform 配置、日志与身份边界

## 配置

技术配置分模块注册，启动必须先验证全部 Options，然后生成只含允许公开字段的稳定 SHA-256 指纹，并进入 Running。出现任何错误时门禁 Faulted，输出中文固定诊断且不启动。未配置的模块不会自动获得默认成功能力。

模块 ID 和公开键使用安全有限字符集；指纹按模块/字段字节序进行稳定排序、规范化编码。秘密值（Token、密码、连接串）不能传给指纹/日志，最多记录“是否配置”的布尔位。此指纹不能替代秘密轮换审计。

## 结构化日志

每条日志携带 Module、可选 World/Entity、Correlation、类别（操作/审计/性能）、严重度、规范事件代码、成功标志和可选非负耗时。禁止自由文本属性、原始异常或原始 Options 进入日志接口。提供结构化 JSON 输出，原始敏感值不可进入事件字段。

## P60.F 安全起点

Security.Contracts 定义认证证据/主体类型、绑定 Port 与命令授权 Port。默认绑定器和默认授权器只拒绝。测试身份与生产身份用不同的类型标志，生产入口的检查拒绝本地测试身份。未接入经验证的生产认证 Adapter 前，所有请求均默认拒绝；不能将这些基础接口视为生产认证实现。

## 架构边界

Platform 不引用游戏模块/World 运行时。Security.Contracts 可依赖 Kernel 的 Result/KernelError。二者作为独立项目进入 P03 manifest。P10 没有数据库、网络、生产 Host，不能声称集成测试已通过。

## 审查与后续边界

P10 CI run #62 已证明抽象启动门禁对非法 Options 会进入 Faulted 并提供固定中文诊断；没有真实 Host，因此不能声称生产宿主已接线。日志安全通过限制事件字段实现，可信模块编写者不能把未验证的用户数据用作 ModuleId；本阶段测试使用敏感哨兵值（非真实秘密）验证脱敏。生产认证 Port 目前只有默认拒绝实现，没有公开的生产身份签发工厂；后续安全阶段必须设计实际可信的认证适配器与主体生命周期。

配置指纹不包含秘密明文，也不跟踪秘密轮换；必须另行记录秘密版本/轮换事件，避免把哈希相等解释为安全配置完全一致。
