## 交付与架构归属

- **StaticData.Abstractions**：中立 Schema/Field/Scalar/Row/Version/Error（领域未来自定义 Ability/Item/World Schema，不放进基础库）。
- **StaticData.Core**：唯一 `StaticCatalogBuilder` 路径验证类型/字段/重复/必填，再按 ID Ordinal 排序；`FrozenStaticCatalog` 与 `FrozenDictionary` 不暴露写入 API；SHA-256 对稳定长度前缀、NFC、Decimal 等规范形式计算，与来源和加载顺序无关。
- **P15.J StaticData.Json**：上限 4MiB UTF-8 文档、固定元数据 `catalog/schemaVersion/dataVersion/records`，严格重复属性/ID、未知字段、空值、类型错误、控字符 ID 拒绝；准确报 SourceName/RowIndex/FieldName，不泄漏原始值。
- **P15.S StaticData.Sql**：P11 参数化 `ParameterizedCommand`、固定公共技术表、可重复读事务读取版本头+记录；SQL 按 `COLLATE "C"` 排序、最多读 10,001 哨兵行，总 JSONB payload 上限 4MiB、单行在大内容返回前就判断字节数、SQL record_id 受长短和 NFC 检查。SQL Adapter 公共 API 只引用 BCL `DbConnection` 工厂委托，底层 P11 Factory 由组合根注入，符合 P03-006。
- 锁文件：四个生产 Assembly 和 Npgsql 10.0.3 的单独 P15 Probe；`LegendsOfTheDungeon.slnx`、P03 Manifest、Unit 引用和 GitHub Actions `staticdata-postgres` 同步。生产无 Npgsql 依赖。
- 协议/技术表 DDL/限制见 [Static Data 模块契约](../modules/STATIC_DATA.md)。

## 四视角独立审查

1. **功能正确性**：同一规范化和冻结 Builder，而非两套近似 Hash；来源顺序、Unicode 表示、Decimal 词法不影响结果；版本与数据内容有明确变化语义。
2. **架构和状态所有权**：领域拥有定义 Schema，通用库无玩法类型和状态写权限；SQL Infrastructure 可以依赖 P11 但公共 API 只暴露 BCL Port，P03-006 负例曾真实失败并已修复。Index 是不可变快照，不涉及运行期切换。
3. **失败恢复**：JSON 类型/字段/版本/重复/上限校验、SQL 参数化与 repeatable-read、超长行在应用分配前拒绝；失败时不发布半成品，DB 错误只返回安全来源错误，不携带连接串/原始 SQL 参数。过期 Catalog 的业务切换属于 P16。
4. **证据和可复现性**：#121–#127 真实 CI 失败都留有首次诊断，未禁用 Analyzer 或 P03 Gate；#128–#131 全五 Job SUCCESS；Hash 一致有真实 PG 18，而非 mock。
