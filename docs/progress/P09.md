## 目标

建立跨模块协作基础：Command→Result、只读 Query、提交后 DeferredEvent，以及显式 Handler 注册/分发。Kernel 只承载消息值契约与延迟事件队列；Handler 注册与运行时分发放在 Runtime.Core，禁止全局 Service Locator。

## 设计决定

1. `CommandId` 为非零 Strong ID；调用边界负责生成，不在 Kernel 内使用 Guid/系统时间。
2. `MessageVersion` 从 1 开始，Command/Query/DomainEvent 都必须显式携带版本。
3. `ICommand<TResult>` / `IQuery<TResult>` / `DomainEvent` 位于 Kernel；不包含 Handler 注册。
4. Query 结果必须实现 `IQuerySnapshot`，语义上是不可变快照；示范模块使用只有 get-only 属性的快照，并用反射测试证明不暴露 public setter/field。
5. `DeferredEventBuffer` 每次 Command 执行独占一个实例，绑定 CommandId，按插入顺序分配从 1 开始的 `EventSequence`。
6. 根事件 depth=0；派生事件记录 parent sequence，depth=parent+1；队列同时限制最大事件数量和最大派生深度。
7. Command Handler 返回成功即表示其领域提交点已完成；Runtime.Core 此后才 Commit DeferredEventBuffer 并调用 publisher。业务失败、取消、异常不会发布已排队事件。
8. publisher 在提交后抛异常时不转成业务失败，异常向上传播给运行时故障隔离；P09 不伪装可以回滚已经提交的领域状态。
9. Handler 重复注册视为启动/组合错误，立即抛 `InvalidOperationException`；未知 Command/Query 返回稳定 `KernelError`。
10. 取消使用标准 `CancellationToken` / `OperationCanceledException` 语义；不可预期 Handler 异常不吞、不转成业务错误。
11. Handler registry/dispatcher 实现位于 Runtime.Core；Kernel 不提供 Service Locator，也不提供任意服务解析 API。
12. 示范模块只放 Unit 测试夹具，证明完整链路；不为了阶段验收制造假的正式业务模块。
