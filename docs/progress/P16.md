## P16.F 设计与边界

领域提供通用 Schema 与引用规则；基础库只认识静态记录 ID、字段名、目标 Catalog 和引用关系，不含 Ability/Item 具体类型。全包候选须具备唯一 Catalog 名称、相同正 DataVersion、有限 Catalog/引用边数；验证每条引用字段的存在性/类型、目标存在、循环（跨 Catalog 和自环）。失败不能泄漏原始记录内容。构建候选只读完整 Bundle/确定性包 Hash 后才允许发布，禁止逐个替换 Catalog。

## P16.R 设计与边界

每个执行域持有一份整包快照；读取须在 Tick 作用域锁定同一包。Prepare 在业务上下文外构造候选，预检失败原快照不变；Commit 只在显式 Tick 边界且无活动视图时原子切换。版本只允许前进，禁止将旧包重新当作新版本。近期历史快照用于 Replay，保留数量与活动版本 pin 有界；不足以安全保留时拒绝 Reload。

活动实例使用中立 Definition Usage（供未来 Cast/Item Owner 映射）：RejectChange 拒绝修改或删除；PinOldVersion 将旧定义与版本保留到使用结束；RequireMigration 默认拒绝变更，除非未来对应 Owner 提供实际迁移机制，本阶段不会假装迁移已完成。P18/P19 World Executor 尚未存在，因此本阶段仅验证 Tick-boundary API 契约而不宣称已接真实 World Tick。
