## 已交付（状态所有者 / 技术 API）

**P16.F**：
- 在原有 `StaticData.Core` 新增 `CatalogReferenceRule`、`CatalogPackageBuilder`、`CatalogPackageSnapshot`、`CatalogPackageException`，所有公共 API 有中文 XML 文档，不引入 NuGet 包或游戏领域定义。
- 领域明确声明引用规则 (sourceCatalog,sourceField,targetCatalog)，源字段必须是 Text；目标值是另一个目录已规范化的记录 ID。可选字段缺失跳过校验，出现但目标不存在必失败。
- 所有目录同一正 DataVersion，重复 Catalog、缺 Catalog、重复/无效规则、缺引用、自环和跨目录环均拒绝；节点使用 (Catalog,Id)，允许不同 Catalog 的同名 ID；迭代 DFS 避免深链栈溢出。
- 整包 16 Catalog / 64 Rules / 131,072 Edges 硬预算，底层 P15 每目录最大 10,000 行、每行最多 64 字段；生成稳定排序与长度前缀 SHA-256（含整包版本、P15 每目录 Hash、排序规则）。任何失败均不发布半包。

**P16.R**：
- `CatalogReloadCoordinator` 每执行域单独拥有，`CaptureTick(logicalTick)` 每次返回固定 `CatalogTickView.Package`；同 Tick 多个视图始终同包，只有全部 Dispose 后才能在显式已完成边界 `CommitAtBoundary` 原子替换整个整包指针。
- `PrepareAsync` 在外部完成加载/DB I/O，`Stage` 注册唯一、版本必须前进的候选；错误准备/取消/错 Tick/旧票据/无活动边界不会改变现有包；Commit 时复查期间新增的活动绑定。
- `RegisterActiveDefinition(Guid,Catalog,RecordId,policy)` 由未来领域 Owner 接线，跟踪最多 4096 个活动引用。RejectChange 拒绝删除/修改；PinOldVersion 保留旧冻结包到句柄 Dispose；RequireMigration 在无真实 Owner 迁移回执时明确拒绝变更，不会假称自动迁移。
- 旧版本 `FindRetained(version,hash)` / `RetainedSnapshots()` 支持有限回放；历史含当前最多 2–16 包，无 Pin 的旧包按需驱逐，Pin 占满时拒绝新 Reload 而不是丢掉活动定义。
- 以上是**技术边界的 Tick 视图和策略**，并非真正 WorldExecutor 或真实 Cast/Item 实例状态；P18/P19/各领域后续绑定权限与迁移。生产持久归档与跨进程 Replay 还需 P62 支持。

## 保留问题与下一阶段依赖

- 目前 PostgreSQL 的两个 Catalog 由各自 RepeatableRead 查询获取并验证共同 DataVersion；**不代表**跨两个独立查询共享同一数据库快照。正式生产包应在发布前冻结来源版本或由后续 Host/存储适配器提供跨 Catalog 一致性策略，禁止重写已发布版本数据。
- 只跟踪中立 ActiveDefinitionPolicy，实际 Cast/Item Owner 对象生命周期与迁移权限尚不存在，默认迁移拒绝而非伪造成功；真实 World Executor/Tick 由 P18/P19 单独验收。
- 历史仅进程内有限保留。长期回放/迁移与多进程同步需 P62/P66；P64 性能数据仍 NOT_RUN。
- P17 下一阶段直接依赖 P15.J/P18/P24，其中 P18/P24 尚未完成；因此 **P17 暂时只能规划，不得越过依赖声明正式验收**。下一安全工作按路线图依赖矩阵可优先推进 P18（依赖 P09/P12，已具备）。
