## 设计决定

1. 强类型标识使用无符号 64 位值，`0` 保留为 default/empty sentinel。
2. CLR 值类型无法禁止 `default(T)`；因此不伪装“无法构造空值”，而是在构造、解析、`Value`/序列化边界明确拒绝 0。
3. `EntityId` 与 `ActorId` 分离；物品不提供含糊的统一 `ItemId`，而是直接提供 `ItemDefinitionId` 与 `ItemInstanceId`。
4. `WorldId` 与 `WorldEpoch` 分离；实体复用版本使用 `EntityGeneration`。
5. Canonical 文本形式为 invariant 十进制非零整数；拒绝符号、空白、0 和超出 `UInt64` 的输入。
6. 不定义任何不同 Strong ID 之间的隐式/显式转换运算符。
7. Error 的机器稳定身份由 lowercase ASCII `Code` 提供；`Message` 是中文/人类可读说明，不作为程序分支稳定键。
8. `Result` / `Result<T>` 的 default 状态为未初始化，读取成功/失败状态时必须抛错，避免 default 被静默解释为业务失败。

## Review 前独立自审

- 9 个 Strong 类型均存在 constructor / IsEmpty / Value / Parse / TryParse / ToString，并共享严格 `StrongIdCodec`。
- Strong ID 之间没有任何 conversion operator。
- 不存在模糊 `ItemId` 类型；Definition/Instance 明确分离。
- canonical 文本：非零 invariant UInt64；拒绝符号、空白、前导零和溢出。
- `default(T)` 被明确视为 empty sentinel；Value/ToString 不能把它静默输出为真实 ID。
- `Result` / `Result<T>` default 状态读取会抛错，不会静默变成业务失败。
- 泛型 factory 位于非泛型 `Result`，避免 CA1000；路线图 Error 概念命名为 `KernelError`，避免 CA1716。
- `KernelError.Code` 仅允许 lowercase ASCII 稳定字符集，最大 96；Message 不作为机器分支键。
- ValidationIssue 集合构造时防御性复制并只读暴露。
- Kernel csproj 仍没有高层 ProjectReference/PackageReference。
- P04 XML 注释 Gate 对首批真实 Public Kernel API 实际生效。
