## 设计决定

1. 强类型标识使用无符号 64 位值，`0` 保留为 default/empty sentinel。
2. CLR 值类型无法禁止 `default(T)`；因此不伪装“无法构造空值”，而是在构造、解析、`Value`/序列化边界明确拒绝 0。
3. `EntityId` 与 `ActorId` 分离；物品不提供含糊的统一 `ItemId`，而是直接提供 `ItemDefinitionId` 与 `ItemInstanceId`。
4. `WorldId` 与 `WorldEpoch` 分离；实体复用版本使用 `EntityGeneration`。
5. Canonical 文本形式为 invariant 十进制非零整数；拒绝符号、空白、0 和超出 `UInt64` 的输入。
6. 不定义任何不同 Strong ID 之间的隐式/显式转换运算符。
7. Error 的机器稳定身份由 lowercase ASCII `Code` 提供；`Message` 是中文/人类可读说明，不作为程序分支稳定键。
8. `Result` / `Result<T>` 的 default 状态为未初始化，读取成功/失败状态时必须抛错，避免 default 被静默解释为业务失败。
