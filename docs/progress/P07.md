## 时间轴与语义

1. `Tick`：从 0 开始的无符号整数逻辑步；可比较、可安全推进，溢出必须失败。
2. `Duration`：非负整数毫秒；0 合法，负数和超出可转换 `TimeSpan` 的值拒绝。
3. `IClock`：只暴露 `CurrentTick`、固定 `TickDuration`、`MonotonicElapsed`；核心 Timer 只依赖这些值。
4. `IAuditClock`：单独暴露 `UtcNow`，用于审计、运维及明确的离线经过时间规则，不能驱动核心 Timer。
5. `FakeClock`：实现两类接口；`AdvanceTicks` 同时推进 Tick 与单调经过时间，`SetUtc` 可独立向前或向后调整 UTC。
6. `LogicalTimer`：纯值状态机；零时长在当前 Tick 即到期，正时长按固定 TickDuration 向上取整到第一个可到期 Tick；取消后永不到期。
7. default `LogicalTimer` 是未初始化状态，查询/取消时拒绝。
8. 路线图中的 “Timer” 概念在 C# API 中命名 `LogicalTimer`，明确不是 `System.Threading.Timer`，也不会为每实体创建系统 Timer。

## 持久化离线时间策略

- 持久化绝对时间只保存 UTC；
- 加载时由 Infrastructure/Adapter 提供当前 UTC，不允许 Domain 自己读取系统时钟；
- 若当前 UTC 早于持久化 UTC（墙钟回拨/数据异常），离线经过时间按 0 处理；
- 正向离线经过时间按完整毫秒向下取整；
- 具体业务必须显式传入自己的最大离线补偿上限，Kernel 只负责 `min(elapsed, maximum)`；
- 核心逻辑 Timer 不持久化墙上时间；可恢复业务应保存业务状态/逻辑截止信息，由所属模块定义恢复策略。

## Review 前独立自审

- 核心时间轴：Tick / MonotonicElapsed / Audit UTC 分离。
- `LogicalTimer`：只读取 `IClock.CurrentTick/TickDuration`，不读取 UTC。
- `FakeClock.AdvanceTicks`：同步推进 Tick + 对应单调时间；溢出前先计算，失败保持状态不变。
- `FakeClock.AdvanceMonotonic`：可单独推进单调时间，不改变 Tick/UTC；测试证明不会使 LogicalTimer 到期。
- `FakeClock.SetUtc`：可前后调整 UTC，不改变 Tick/Monotonic；测试证明墙钟跳变不改变 Timer。
- 时间 Unit/生产源码中没有 `Thread.Sleep`、`Task.Delay`。
- Kernel 生产源码没有 `DateTime.UtcNow`、`DateTimeOffset.UtcNow`、`Stopwatch`、`System.Threading.Timer`。
- `Duration`：非负整数毫秒；0 合法；支持范围始终可精确转 TimeSpan；比较与算术溢出有测试。
