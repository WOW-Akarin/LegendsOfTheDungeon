# 工作恢复与进度维护流程

> 适用：所有 P00–P67 阶段、基础子任务和跨阶段修复任务。  
> 状态真相：当前状态写在 `PROGRESS.md`；阶段历史写在 `progress/Pxx.md`；`CONTEXT.md` 只保存恢复所需摘要。

## 1. 恢复读取顺序

1. 读取 `PROJECT_SPEC.md`、`CONTEXT.md`、`PROGRESS.md`。
2. 打开 PROGRESS 链接到的 `DEVELOPMENT_ROADMAP.md` 阶段、Accepted ADR 和模块文档。
3. 核对真实 Branch、HEAD、任务起始 SHA 与可获得的工作区差异。
4. 重现当前 FAIL，或确认为什么某项仍为 NOT_RUN/N/A。
5. 从“当前停点”继续，不从聊天记忆或旧计划推断完成状态。

若仓库事实与摘要冲突，以仓库、测试和持久证据为准，先修正文档再继续。

## 2. 合法状态

只允许：

`NOT_STARTED → IN_PROGRESS → REVIEW → ACCEPTED`

补充分支：
- `IN_PROGRESS ↔ BLOCKED`
- `REVIEW → IN_PROGRESS`（退回修正）
- `NOT_STARTED/IN_PROGRESS → DEFERRED`（必须记录范围依据、影响、恢复计划）

`DEFERRED` 不是完成；`NOT_RUN` 是验证结果而不是阶段状态。

## 3. 必须更新 PROGRESS 的触发点

- 开始任务；
- 重要子任务完成；
- 契约、状态所有权、ADR、依赖变化；
- 验证结果变化；
- 出现或解除阻塞；
- 大重构前后；
- 进入 REVIEW；
- ACCEPTED / DEFERRED；
- 当前摘要失真或工作结束。

## 4. CONTEXT 压缩规则

CONTEXT 仅保留：
- 当前范围；
- 当前仍有效的架构不变量；
- 当前里程碑/阶段；
- 已由证据证明的能力；
- 当前任务、停点、下一安全动作与成功条件；
- 活跃阻塞/风险；
- 关键契约、所有权、Accepted ADR、AC 基线和入口链接。

移除：
- 已解决且不会影响恢复的过程细节；
- 聊天全文；
- 重复的规范正文；
- 过时的下一步；
- 无证据的“已经实现”描述。

历史原因和验收结论迁入 `progress/Pxx.md`。

## 5. 阶段归档规则

每个阶段使用 `progress/Pxx.md`，至少包含：
- 任务起始/最终代码基线；
- 依赖快照；
- 交付物；
- PASS/FAIL/N/A/NOT_RUN 验证矩阵；
- 修改文件与契约/ADR/所有权变化；
- 风险与未验证假设；
- 四视角自审；
- 恢复步骤；
- 实现提交与 Review 结论。

路线图不维护第二套完成勾选状态。

## 6. BLOCKED 最小记录

发生 BLOCKED 时，必须记录：
1. 阻塞前状态；
2. 阻塞原因；
3. 缺失的契约/数据/决定；
4. 影响的阶段/子任务；
5. 仍可继续的工作；
6. 下一安全动作；
7. 解除条件。

禁止通过访问 Internal/Infrastructure、固定成功返回、跳过测试或临时万能服务“解除”阻塞。

## 7. 自优化边界

流程优化只能在不降低现有验收标准的前提下进行：
- S0：说明/示例/纠错，记录原因和位置；
- S1：新增质量约束，记录影响、成本、适用时间和存量迁移；
- S2：范围/核心模型/所有权/验收标准变化，必须走 ADR。

模板可以精简重复项，但不能把必需证据删除、改成可选或把 NOT_RUN 解释为通过。
